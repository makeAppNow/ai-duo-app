# 2장. AI와 일하는 법: 첫 프로젝트부터 규칙서까지

책 본문에 나온 프롬프트, 터미널 명령, 예제 파일을 나온 순서대로 모았습니다. 앞뒤 설명은 책을 함께 봐 주세요.

## 이야기 중에

**AI에게**

```text
새 브랜치로 워크트리를 만들어서 거기서 작업해줘.
```

## 기본 2-1. 첫 프로젝트 만들고 깃허브에 올리기

**터미널** · 터미널에서 그 폴더로 이동하고 클로드 코드를 실행한다.

```bash
cd Desktop/my-app
claude
```

**AI에게** · 순서대로 한 문장씩.

```text
여기에 아이폰이랑 안드로이드 둘 다 되는 앱 프로젝트를 만들어줘. 리액트 네이티브랑 엑스포로.
```

**AI에게**

```text
비밀번호나 키가 들어 있는 파일이 같이 올라가지 않게 확인해줘.
```

**AI에게**

```text
깃 세팅해줘. 그리고 깃허브에 비공개로 올려줘. 계정은 만들어뒀어. 내가 눌러야 하는 게 있으면 알려줘.
```

## 기본 2-2. 규칙서 첫 버전

**AI에게** · 클로드 코드에는 규칙서 초안을 만들어주는 명령이 따로 있다.

```text
이 프로젝트를 훑어보고, 네가 앞으로 지킬 규칙서 초안을 CLAUDE.md로 써줘. 지금은 짧아도 돼.
```

**AI에게**

```text
CLAUDE.md에 아래 규칙도 추가해줘.
- 요청받지 않은 기능을 추가하지 말 것
- 불명확하면 멈추고, 무엇이 혼란스러운지 말하고, 질문할 것
- 커밋까지만 한다. 푸시는 사람이 누른다
```

## 자동화: 두 번째부터는 파일이 일한다

**파일**

```
---
name: project_splash_logo_intro
description: 앱 실행 인트로(스플래시 배경 + 로고 등장 애니메이션) 구현 상태와 결정 근거
---
⚠️ iOS 앱 아이콘 확대는 스플래시가 아니다. 스플래시보다 먼저 나오고
앱이 제어할 수 없다. 이 증상으로 스플래시를 네 번 잘못 팠다.
교훈: 네이티브에 구워지는 것(스플래시·아이콘)은 눈에 띄는 색으로 바꿔
한 번 빌드하는 실험이 파일 재확인보다 빠르다.
```

**AI에게** · 오늘 정한 걸 남길 때.

```text
오늘 정한 것과 그 이유를 기억 파일로 남겨줘. 다음 세션에서 같은 걸 다시 묻지 않게, 무엇을 정했는지와 왜 그렇게 정했는지를 같이 적어줘.
```

**파일**

```
---
name: ship
description: 완성된 작업을 머지하고 push 후 TestFlight(internal)까지 배포하는
  원스톱 출하 스킬. 사용자가 "/ship", "머지하고 테플까지" 등을 요청하면 사용. …
---
## 사전 조건 (실패 시 즉시 중단하고 사용자에게 알림)
## 절차
### 1. 변경 파악 및 브랜치 분리 판단
### 2. 커밋 확보
### 3. 머지 확인 및 선택
### 4. push 전 검증 게이트 (전부 통과 시에만 push)
### 5. TestFlight 문구 구성
### 6. 빌드 + 업로드
### 7. 마무리
```

**AI에게** · 손으로 해본 절차를 매뉴얼로 굳힐 때.

```text
방금 우리가 한 순서(테스트 → 빌드 → 테스트플라이트 업로드)를 스킬로 만들어줘. 이름은 ship. 단계마다 성공했는지 확인하고, 하나라도 실패하면 거기서 멈추고 무엇이 실패했는지 보고하게 해줘.
```
